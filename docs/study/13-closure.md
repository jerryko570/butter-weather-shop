# 13. 클로저 — 함수가 "바깥 값"을 도시락처럼 싸들고 다니는 것

> 한 줄: **클로저 = 함수가 자기 "바깥에서 받은 값"을 계속 기억하는 것. 바깥 함수가 끝나도 안 잊어버린다.** 이름은 어렵지만 개념은 "함수가 바깥 값을 품고 다닌다" 하나뿐.
> 커링 편에서 처음 나옴 [[07-currying-create]] · 함수 문법 밑바닥 [[11-function-syntax]] · persist 실행 타이밍 [[11-function-syntax]] ⑬.

---

## 🎯 한 줄 정의

> **클로저 = "함수" + "그 함수가 기억하는 바깥 값들" 한 세트.**

함수가 태어날 때 주변에 있던 값을, 나중에 불려도 **여전히 기억**하고 있는 현상.

---

## 1단계 — 함수는 "바깥 값"을 쓸 수 있다

```js
function add(a) {
  return function (b) {
    return a + b     // ← 안쪽 함수가 "바깥"의 a를 씀
  }
}
```

안쪽 함수가 자기 것도 아닌 `a`(바깥 함수 것)를 갖다 쓴다. 여기까진 그냥 "바깥 변수 접근".

---

## 2단계 — 신기한 점: 바깥 함수가 끝나도 `a`가 안 사라진다 ⭐

보통 함수가 끝나면 그 안의 변수는 **사라진다.** 근데:

```js
const addThree = add(3)   // add(3) 실행 끝남 → 보통이면 a=3도 사라져야 함
addThree(4)   // 7   ← 근데 a=3을 여전히 기억!
addThree(10)  // 13  ← 여전히 3 기억!
```

- `add(3)`은 이미 **끝났는데도**, 안쪽 함수가 `a=3`을 **붙들고 안 놓는다.** → 이게 **클로저**.
- **왜 안 사라지나?** 안쪽 함수가 `a`를 아직 쓰고 있으니, 자바스크립트가 "얘 아직 필요하네" 하고 **안 지우고 살려둔다.**

---

## 🎒 도시락 비유

```
함수가 태어날 때 → 주변에 있던 값(a=3)을 도시락에 싸서 들고 나옴
나중에 불릴 때   → 그 도시락 열어서 a=3을 꺼내 씀
```

- 함수 = 도시락 들고 다니는 사람
- 클로저 = 그 **도시락(기억한 바깥 값)** 까지 합친 것
- 바깥 함수가 끝나 집(스코프)이 사라져도, **도시락은 계속 들고 다닌다.**

---

## ⚠️ 누가 클로저를 갖나 — "만든 건 바깥, 가진 건 안쪽"

제일 헷갈리는 지점. **클로저는 "바깥 함수"가 아니라 "리턴돼서 살아남는 안쪽 함수"가 가진다.**

```js
function add(a) {           // ← 바깥 함수: 값(a=3) 만들고 → 끝나서 사라짐 💨
  return function (b) {     // ← 안쪽 함수: 살아남아 a=3을 품음 = 클로저 ✅
    return a + b
  }
}
const addThree = add(3)    // add는 리턴하고 끝 (사라짐) / 안쪽 함수만 살아남음
addThree(4)   // 7          // 살아남은 안쪽이 a=3을 품고 있어서 계산됨
```

- **바깥 함수** = 값을 **만들어주고** → 안쪽 리턴하고 → **일 끝, 사라짐**
- **안쪽 함수** = 리턴돼서 **계속 살아있음** + 그 값을 **품고 다님** ← 클로저를 가진 쪽

🎒 **엄마-도시락:** 바깥 함수 = 도시락 싸주고 집에 가는 엄마(역할 끝) / 안쪽 함수 = 도시락 들고 나가는 사람(계속 들고 다님). **도시락(클로저)을 가진 건 나간 사람(안쪽).**

> ⚠️ 헷갈리는 이유: 값(`a=3`)을 **만든** 건 바깥이라 "바깥 게 아닌가?" 싶다.
> → **"만든 사람"과 "가진 사람"이 다르다.** 만든 건 바깥(끝나서 사라짐), **품고 기억하는 건 안쪽**.

---

## 🛒 우리 프로젝트에서 — persist가 `name`을 기억하는 법

```ts
persist(콜백, { name: 'butter-weather-cart' })
  → persist가 만든 "감싼 스토어"가 name='butter-weather-cart'를 도시락에 싸둠
  → 나중에 저장할 때 도시락에서 name 꺼내 씀
```

- persist 실행이 **끝나도**, persist가 만든 "감싼 스토어"가 `name`을 **계속 기억**.
- 그래서 items 바뀔 때마다 → 그 품은 `name`으로 `localStorage['butter-weather-cart']`에 저장.
- 새로고침 후에도 → 같은 `name` 이름표로 찾아 복원.

→ `add(3)`이 3을 기억하던 그 원리 그대로. **바깥(내가 준 인자 name)을 안쪽(persist가 만든 스토어)이 품고 계속 기억 = 클로저.**

```
[persist 실행]
   인자로 받은 name ──┐
                      ↓
   ┌─────────────────────────────────┐
   │  감싼 스토어 (리턴됨)              │
   │   🎒 name='butter-weather-cart'   │ ← 품고 있음 (클로저)
   │   저장 로직: 🎒에서 name 꺼내 씀    │
   └─────────────────────────────────┘
```

---

## 🔗 이미 본 클로저들 (이 프로젝트 곳곳에)

내가 안 부르고 넘긴 콜백들도, 정의될 때 주변 값을 품는다 = 클로저.

| 코드 | 품은 바깥 값 |
| --- | --- |
| `persist(콜백, {name})` → 감싼 스토어 | `name` |
| `addItem: (item) => set(...)` | (그 스코프의 `set`) |
| `useProduct = (slug) => { ... .eq('slug', slug) }` | `slug` |

→ "함수가 자기 밖의 값을 계속 쓰는" 곳은 전부 클로저가 일하는 중.

---

## ✅ 한 눈 요약

```
클로저 = 함수가 "바깥에서 받은 값"을 계속 기억하는 것
       = 함수 + 그 함수가 품은 바깥 값 (한 세트)

신기한 점: 바깥 함수가 끝나도 그 값이 안 사라짐
          (안쪽 함수가 쓰고 있으면 자바스크립트가 살려둠)

비유: 태어날 때 주변 값을 도시락🎒에 싸서 → 나중에 꺼내 씀

예:  add(3) → 3을 기억하는 addThree
     persist(콜백, {name}) → name을 기억하는 감싼 스토어
     useProduct(slug) → slug를 기억하는 queryFn
```

> 🔑 이름(클로저)은 지금 안 외워도 됨. **"함수가 바깥 값을 기억한다"** 느낌만 잡으면 충분.
> 여러 번 만나면 자연스럽게 이름이 붙는다.
