# 16. set이 하는 일 + 클로저 방향 + return{items} 병합 (addItem "쓰기" 절반)

> 한 줄: **`set`은 "생성"이 아니라 "갱신(쓰기)"이다. 콜백이 새 값을 계산하면 `set`이 창고에 써넣는다. 그리고 클로저는 값(set)이 아니라 "그 값을 꺼내 쓰는 함수(addItem)" 쪽이다. return은 배열만 주지 않고 `{ items: 배열 }`로 감싸야 set이 "어느 칸"인지 알고 병합한다.**
> find로 찾기 [[15-find-dot-notation]] · 클로저 기초 [[13-closure]] · 스토어 해부 [[09-store-anatomy]] · 리턴 [[14-return]] · 함수 채우는 주체 [[11-function-syntax]]

## 오늘 뜯은 코드

```ts
addItem: (item) =>
  set((state) => {
    const existing = state.items.find((i) => i.id === item.id)
    if (existing) {
      return {
        items: state.items.map((i) =>
          i.id === item.id ? { ...i, quantity: i.quantity + 1 } : i
        ),
      }
    }
    return { items: [...state.items, { ...item, quantity: 1 }] }
  })
```

---

## 1. `set`이 하는 일 = 생성이 아니라 "갱신(쓰기)"

| | 언제 | 누가 | 무엇을 |
| --- | --- | --- | --- |
| **생성** | 앱 켤 때 **딱 1번** | 콜백함수 `(set,get)=>({...})` 실행 | 창고 태어남 (`items: []`) |
| **갱신** (`set`) | 담기 클릭할 때 **매번** | `set` | 창고 값을 새로 써넣음 |

- ⭐ **생성은 `set` 부르기 "전에" 이미 끝나 있다.** 첫 클릭도 "빈 배열 `[]` → `[상품]`"으로 바꾸는 **갱신**이지 생성이 아니다.
- 냉장고 비유: **생성** = 냉장고 처음 설치(1번) / **`set`** = 안의 우유 채워넣기(매번). 우유 처음 넣는 것도 "냉장고 생성"이 아님.

### set의 3가지 일

```
콜백이 { items: 새배열 } 을 계산해 리턴하면 → set이:
  1️⃣ 창고에 써넣기 (반영)   기존 배열 고치는 게 아니라 "새 배열로 교체"
  2️⃣ 병합 (merge)          넘긴 키만 갈아끼우고 나머진 그대로 (아래 4번)
  3️⃣ 리렌더 + persist 저장  구독 컴포넌트 다시 그림 + localStorage 백업
```

> ⭐ **역할 나누기: 계산은 콜백이, 써넣기는 set이.** 이게 오늘의 결론.

## 2. 클로저 — "값"이 아니라 "함수" 쪽이다 (방향 주의)

```ts
(set, get) => ({                     // set = 바깥에 사는 "값"
  addItem: (item) => set(...)        // 이 함수 전체 = 클로저
})
```

- **기억하는 것** = 함수 `(item) => set(...)` **전체** = **클로저** = `addItem`
- **기억되는 값** = `set` (바깥 스코프의 변수)
- ⚠️ `set` 자체도, `set()` 호출도, `item`(매개변수)도 **클로저 아님.** 클로저는 **함수 통째로.**

### 방향이 핵심

```
클로저(addItem) ───꺼내 씀──→ set     ✅ 이 방향
set ───받음──→ 클로저                  ❌ 아님 (우유가 사람을 마실 순 없음)
```

- 🥛 `set` = 냉장고 안 **우유**(기억되는 값) / `addItem` = 우유 **꺼내 마시는 사람**(클로저)
- 클로저가 꺼내 쓰는 건 **매개변수만이 아님.** 바깥 변수면 뭐든(const·let·매개변수). `set`은 마침 바깥 콜백의 **매개변수**였을 뿐.
- 같은 `set` **하나**를 안쪽 함수들(addItem·removeItem·clearCart…)이 전부 **다시 꺼내 쓴다.** (zustand가 앱 켤 때 1번 할당 → 이후 계속 재사용)

## 3. 삼항 연산자 `조건 ? A : B` — 한 줄 if-else

```ts
i.id === item.id ? { ...i, quantity: i.quantity + 1 } : i
└──────┬───────┘   └────────────┬────────────────┘   ┬
    ① 조건            ② 참일 때 값               ③ 거짓일 때
```

- 부분이 **3개**라서 "삼(三)항". 기호는 `?`(물음표) `:`(콜론).
- if로 풀면 완전히 같은 뜻:

```ts
if (i.id === item.id) { return { ...i, quantity: i.quantity + 1 } }
else                  { return i }
```

- `.map()` 안에서는 요소마다 **값 하나를 리턴해야** 해서 삼항이 궁합 좋음.
- 안 맞는 것도 `: i`로 **그대로 리턴**해야 배열이 안 깨짐 (map은 모든 요소에 뭔가 리턴해야).

## 4. spread `{ ...i, quantity: i.quantity + 1 }` — 복사 후 덮어쓰기

실제 값으로 보면 (사과키링 2개 담긴 상태):

```ts
i = { id:'abc', name:'사과키링', price_krw:5000, quantity:2 }

{ ...i, quantity: i.quantity + 1 }
// 1단계 ...i    → { id:'abc', name:'사과키링', price_krw:5000, quantity:2 }  (통째로 복사)
// 2단계 quantity → { id:'abc', name:'사과키링', price_krw:5000, quantity:3 }  (quantity만 덮어씀)
```

- `...i` = i의 **모든 키:값을 꺼내 새 객체에 펼쳐 넣기** (복사)
- ⚠️ **순서가 이긴다** — `...i` 뒤에 `quantity:3`이 와서 앞의 `quantity:2`를 덮음. 순서 반대면 안 먹힘.
- 왜 복잡하게? `i.quantity = ...`(직접 수정) 대신 **새 객체**를 만드는 것 = **불변성** (React가 바뀐 걸 알아채려면 새 객체여야). → 다음 주제

📄 서류 원본 복사기로 복사(`...i`) → 복사본에서 수량 칸만 새로 적기(`quantity:+1`). 원본은 그대로.

## 5. ⭐ 왜 `return { items: 배열 }`? — set한테 "어느 칸"인지 알려주기 = 병합

창고는 **여러 칸(키)이 있는 객체**:

```ts
{ items:[...], isOpen:false, addItem:fn, removeItem:fn, ... }
```

배열만 딸랑 주면 set이 헷갈림 — "이 배열을 어디에 넣지? items? isOpen?"
그래서 `{ items: 배열 }`로 **감싸서** "**items 칸에** 넣어"라고 라벨을 붙인다.

```ts
return { items: state.items.map(...) }
        └─┬─┘  └────────┬─────────┘
       어느 칸        새 값
```

### 병합(merge) = 준 칸만 바꾸고 나머진 그대로

```
바꾸기 전: { items:[사과],     isOpen:false, addItem:fn }
return:    { items:[사과,배] }              ← items만 줌
바꾼 후:   { items:[사과,배], isOpen:false, addItem:fn }
                  └─┬─┘        └────┬──────────────
              items만 바뀜      나머진 그대로 (병합)
```

🗄️ 창고에 서랍 여러 개(items·isOpen·함수들). set한테 물건 주며 **"items 서랍에 넣어"** 라벨(`{items:...}`)을 붙여야 어느 서랍인지 앎. → if 두 갈래 다 `{ items: ... }` 모양인 이유(둘 다 "items 칸을 바꾼다"는 같은 일).

## 6. ⭐ 중첩 구조(층) + `{ }` 코드블록 규칙

### 함수는 층으로 겹친다 — 무한 중첩 가능

함수 안에 함수, 그 안에 또 함수. `addItem` 하나가 이미 **4겹**:

```ts
addItem: (item) =>                                    // 함수①
  set((state) => {                                    // 함수② + 코드블록 {
    const existing = state.items.find((i) => ...)     //   함수③ (find 콜백)
    if (existing) {                                   //   if 코드블록 {
      return { items: state.items.map((i) =>          //     함수④ (map 콜백)
        i.id === item.id ? { ...i, quantity: i.quantity + 1 } : i
      )}
    }                                                 //   }
  })                                                  // }
```

```
함수①(addItem)
 └ 함수②(set 콜백) → 코드블록 {
     └ 함수③(find 콜백)
     └ if → 코드블록 {
         └ 함수④(map 콜백)
       }
   }
```

- **함수 → 블록 → 함수 → 블록 → 함수** 무한히 깊어질 수 있음(문법상 제한 없음).
- 🎨 Figma 레이어랑 같음: 그룹 안 그룹 안 요소 = 함수 안 함수 안 문장. **디자인 근육 그대로 통함.**
- `}` `)` 여러 개 겹쳐 닫혀도 안 무서움 — "층이 닫히는 것"으로 읽으면 됨.

### `{ }` 코드블록 규칙 — 안/바깥 무관! 문장 개수가 기준 ⚠️

```
할 일 1개    → { } 생략, 바로 리턴     (item) => set(...)
할 일 여러 개 → { } 열고 여러 문장       (state) => { const...if...return }
```

- ❌ "바깥 함수는 코드블록 못 쓴다" = **틀림.** 어느 함수든 `{ }` 쓸 수 있음.
- ✅ 기준은 **위치(안/바깥)가 아니라 문장이 1개냐 여러 개냐.**
- `addItem`이 `{ }` 안 쓴 건 "바깥이라서"가 아니라 **할 일이 `set(...)` 하나뿐이라서.** 아래처럼 써도 똑같이 작동:

```ts
addItem: (item) => set((state) => {...})   // 지금 (한 방이라 생략)

addItem: (item) => {                       // ↓ 이렇게 써도 완전히 같음
  const x = item.name.trim()   // 바깥 함수에서 const OK!
  if (!item.id) return         // 바깥 함수에서 if OK!
  set((state) => {...})
}
```

> 이 파일에서 마침 바깥=한 방(생략)·안쪽=여러 줄(블록)이라 "바깥은 생략, 안쪽은 블록"처럼 보이지만 **우연.** 위치 규칙 아니라 문장 개수 규칙.

## ✅ 한 눈 요약

```
set = 갱신(쓰기), 생성 아님
  생성은 앱 켤 때 콜백 1번 → 창고(items:[]) 태어남. set 부르기 전에 끝
  set의 일: ① 새 값으로 교체(반영) ② 병합 ③ 리렌더+저장
  ⭐ 계산은 콜백이, 써넣기는 set이

클로저 = 값(set)이 아니라 함수(addItem) 쪽
  기억하는 것=함수 전체 (item)=>set(...) / 기억되는 값=set
  방향: 클로저 → set 꺼내 씀 (set이 클로저를 받는 게 아님)
  꺼내 쓰는 값은 매개변수만이 아님 = 바깥 변수면 뭐든

삼항 조건 ? A : B = 한 줄 if-else (부분 3개라 삼항)
  map 안: 맞으면 새 객체, 안 맞으면 : i 그대로 (모든 요소 리턴해야)

spread {...i, quantity:i.quantity+1} = 복사 후 덮어쓰기
  ⚠️ 순서가 이긴다 (뒤엣것이 앞엣것 덮음)
  원본 안 건드리고 새 객체 = 불변성

return { items: 배열 } = set한테 "items 칸"이라고 알려주기
  병합: 준 키만 바꾸고 나머지(isOpen·함수들)는 그대로

⭐ 중첩 구조: 함수→블록→함수→블록 무한 겹침 (addItem 이미 4겹, Figma 레이어)
{ } 코드블록: 안/바깥 무관! 문장 1개면 생략 / 여러 개면 { } 엶
  addItem이 { } 없는 건 "바깥이라서"가 아니라 할 일이 set 하나뿐이라서
```
