# 11. 함수 문법 밑바닥 — 뱉기·부르기·넣기·만들기

> 한 줄: **함수를 "값을 뱉는(return) 상자"로 보는 관점. 인자↔매개변수 방향, 이름()=부르기, 누가 채우나, 콜백이 객체를 뱉는 것까지 — 제일 여러 번 되물으며 잡은 기록.**
> 데이터 흐름 전 구간은 [[10-data-flow-trace]] · 스토어 해부는 [[09-store-anatomy]] · 커링은 [[07-currying-create]].

---

## 🎯 오늘의 큰 깨달음 한 줄

> **함수 = 값을 하나 "뱉는(return)" 상자.** 그 뱉는 값이 숫자일 수도, **객체**일 수도 있다.

나머지 개념(persist·콜백·리모콘)은 전부 이 한 줄 위에 얹힌다.

---

## ① 뱉는다 = return (같은 말)

```ts
const 더하기 = () => { return 3 }   // 3을 "뱉는다"
const 더하기 = () => 3              // 위랑 똑같음 (=> 뒤 바로 값 = return 생략)
```

- **뱉는다 = 던진다 = 돌려준다 = 결과를 낸다 = `return`.** 전부 한 말.
- `=>` 뒤에 값이 바로 오면 **return이 숨어있는** 것. `() => 3` = "3을 return".

---

## ② 함수는 "객체"도 뱉을 수 있다 (제일 헤맴)

```ts
const 만들기 = () => ({ name: '키링' })   // 부르면 → { name:'키링' } 객체를 뱉음
```

→ **함수가 객체를 뱉는다 = "함수가 객체를 만든다".** ("만든다 = 객체를 return한다")

### ⚠️ `=> ({...})` 소괄호의 정체

```ts
() => ({ ... })   // 소괄호 O → "이 객체를 return해라"
() => { ... }     // 소괄호 X → 그 {}는 객체가 아니라 "코드 블록"
```

객체를 뱉고 싶으면 **`({...})` 소괄호로 감싼다** = "이건 객체야" 표시.

### 네 코드가 이거

```ts
(set, get) => ({          // 이 콜백을 부르면
  items: [],
  addItem: (item) => set(...),
})                        // 이 객체 덩어리를 "만들어 뱉음"
```

> 🐟 **붕어빵 틀**: 틀(콜백)을 누르면(부르면) → 붕어빵(객체)이 나온다.

---

## ③ 이름() = "부른다(호출)"

```ts
persist(...)   // persist를 "부른다" (괄호 열었으니까)
addItem({...}) // addItem을 "부른다"
openCart()     // openCart를 "부른다" (넣을 값 없음 = 빈 괄호)
```

- **함수 이름 뒤에 괄호 `()` 를 여는 것 = 그 함수를 부르는 것.**
- 괄호 **안 열면** = 아직 안 부름 (이름만 가리킴 = 참조).

```ts
return useQuery        // ❌ 함수 "자체"를 리턴 (괄호 없음)
return useQuery(...)   // ✅ 부른 "결과"를 리턴 (괄호 있음) ← 우리 코드
```

---

## ④ 인자 = IN / return = OUT (방향이 반대!)

```
인자 (넣는 재료)  →→→  [ 함수 ]  →→→  return (나오는 결과)
     들어감(입력)                    나옴(출력)
```

- **인자** = 함수 **안으로 넣는** 것
- **return** = 함수가 **밖으로 뱉는** 것
- **넣은 걸 도로 뱉는 게 아니다.** 재료로 **새 결과**를 만들어 뱉는다.

```ts
persist( 콜백, 옵션 )   // 넣는 것(인자): 콜백·옵션 2개
//   ↓ 뱉는 것(return): "자동저장 기능 씌운 스토어" 1개  ← 새로 만든 다른 것
create()( ↑그 결과 )
```

> 🐟 반죽·팥(인자) 넣으면 → 붕어빵(return)이 나옴. 반죽이 도로 나오는 게 아님.

---

## ⑤ 인자 vs 매개변수 — `=>` 로 3초 판별

```
괄호 뒤에 =>  있다   →  그 괄호 안 = 매개변수 (정의: 빈칸 만드는 중)
이름 뒤 괄호만 있다   →  그 괄호 안 = 인자    (호출: 값 넣는 중)
```

```ts
addItem({...})                          // => 없음 → { }는 인자
addItem: (item) => set(...)             // => 있음 → item은 매개변수
getNextPageParam: (lastPage, allPages) => ...  // => 있음 → 둘 다 매개변수
initialPageParam: 0                     // => 없음 → 그냥 값(함수 아님)
staleTime: 1000 * 60 * 5                // => 없음 → 그냥 값
```

| | 인자 (argument) | 매개변수 (parameter) |
| --- | --- | --- |
| 뭐냐 | 실제 값 (넣는 것) | 빈칸 이름표 (받는 자리) |
| 언제 | 부를 때 | 정의할 때 |
| 표시 | `이름(...)` | `(...) =>` |

---

## ⑥ 누가 채우나 — "부르는 사람 = 채우는 사람"

내가 **정의만 하고 안 부르는** 함수는, **부르는 라이브러리가 매개변수를 채운다.**

| 함수 | 매개변수 | 누가 채워? |
| --- | --- | --- |
| `queryFn: ({ pageParam }) =>` | pageParam | 리액트쿼리 |
| `getNextPageParam: (lastPage, allPages) =>` | lastPage, allPages | 리액트쿼리 |
| `addItem: (item) => set((state) =>` | state | zustand |
| `.find((i) =>` | i | find |

→ 내가 `getNextPageParam(...)` 직접 부른 적 없지? **넣을 기회가 없으니** 부르는 쪽이 채운다.

---

## ⑦ 반전: "만든 사람 ≠ 부르는 사람" (persist의 교차 구조)

**persist를 부르는 건 zustand가 아니라 "나(내 코드)".**

```ts
create()(
  persist(                    // ← 이 persist(...)를 부르는 건 "내 코드"
    (set, get) => ({...}),    // ← 이 콜백을 부르는 건 "zustand"
    { name: '...' }
  )
)
```

| | 누가 **만들었나** | 누가 **부르나** | 값은 누가 넣나 |
| --- | --- | --- | --- |
| `persist(...)` | zustand (제공) | **나** | **나** (콜백·옵션 = 인자) |
| 콜백 `(set,get)=>` | **나** | zustand | **zustand** (set·get = 매개변수) |

> **딱 엇갈린다.** persist = zustand가 만들고 내가 부름 / 콜백 = 내가 만들고 zustand가 부름.
> 그래서 규칙은 "만든 사람"이 아니라 **"부르는 사람이 채운다".**

---

## ⑧ set·get = zustand가 쥐어주는 "리모콘"

```ts
(set, get) => ({ items:[], addItem: (item) => set(...) })
```

- `set` = **쓰기 리모콘** (상태 바꾸기) / `get` = **읽기 리모콘** (현재 상태 꺼내보기)
- zustand가 콜백 부를 때 `(set, get)` 빈칸에 **리모콘을 쥐어줌.**
- 콜백은 그 리모콘을 **함수들(addItem 등) 속에 "심은 채로" 객체를 만들어 뱉음.**
- 심어둔 `set` 리모콘은 **나중에 addItem이 불릴 때** 눌려서 상태를 바꿈.

> **시점 구분**: 만들 때(지금) = 리모콘 심기 / addItem 부를 때(나중) = 리모콘 누르기.

---

## ⑨ 함수 = 규칙 덩어리

> **함수 하나 = 약속(규칙) 하나.** "이 값(인자)을 받으면 → 이렇게 처리해서 → 이걸 뱉는다(return)."

| 규칙 | 뭐냐 | 어디 적혀있나 |
| --- | --- | --- |
| **뭘 받나** | 인자 (순서·의미까지 정해짐) | 정의의 `(...)` |
| **어떻게 하나** | 처리 내용 | `=>` 뒤 코드 |
| **뭘 뱉나** | 리턴 | `return` |

```ts
updateQuantity: (id, quantity) => ...   // 규칙: 1번=id, 2번=quantity
```

- **인자는 순서·의미가 정해진 규칙** → 부를 때 그 순서대로 넣어야 함 (자리 바뀌면 엉킴).
- **규칙은 함수 "정의"에 적혀있다.** 내 함수면 내 파일에, 라이브러리 함수(persist)면 그쪽/공식문서에.
- 그래서 **"함수를 안다 = 그 규칙을 안다".** 새 함수 보면 "얘 규칙이 뭐지?"로 접근.

> 🍳 함수=레시피 / 인자=재료(1번 밀가루·2번 설탕, 순서 정해짐) / 처리=본문.

---

## ⑩ persist 완전정복 — 인자 역할 + "리턴까지만"

```ts
persist( 인자1(콜백), 인자2(옵션) )
//       └─ 무엇을 ─┘  └─ 어떻게 ─┘
//        감쌀 대상      감쌀 방법(설정)
```

- **인자1 = "무엇을"** → 감싸질 **대상**(콜백, 내용물)
- **인자2 = "어떻게"** → 어떻게 감쌀지 **설정**(`{name:'butter-weather-cart'}` = localStorage 방 이름)
- 둘 다 감싸이는 게 아니라, **인자1을 인자2 설정대로** 감싼다.

### persist는 "감싸서 리턴하면 끝" — 실행은 딴 애가

```
① 내가 persist(인자1, 인자2)를 실행(부름)        ← 실행 주체 = 나
② persist가 인자1을 인자2 설정으로 감쌈
③ persist가 새것(자동저장 스토어)을 리턴          ← persist 일 여기서 끝!
④ create()가 그 새것을 받아 useCartStore 완성     ← 다음 단계
⑤ (나중) zustand가 콜백을 실행 → 객체 생성        ← 이때 콜백이 돎
```

- **persist가 결과를 "실행"하는 게 아니다.** persist는 ②③(감싸서 리턴)만 하고 손 뗌.
- persist를 **실행(부르는)** 건 **나.** 리턴한 걸 쓰는 건 create, 콜백을 실제로 돌리는 건 zustand(나중).
- ⚠️ persist 부를 때 **콜백은 아직 실행 안 됨** → 그래서 persist가 "콜백의 결과값(객체)"을 리턴할 수 없음. persist가 리턴하는 건 **감싼 스토어**(≠ 콜백이 뱉는 객체).

### 리턴은 밖으로 OUT (콜백에 저장 ❌)

```ts
(set, get) => ({...})   // 콜백이 이 객체를 "뱉어서 밖으로" → 부른 zustand가 받아감
```

- 리턴 = 항상 **밖으로 나간다.** 콜백 **안에 저장되는 게 아니라** 부른 쪽으로 감.
- 🐟 붕어빵은 틀 안에 쌓이는 게 아니라 밖으로 나와 받는 사람(zustand)이 가져감.

> 🍳 persist=요리사: 내가 재료 주고 "해줘"(①) → 업그레이드된 도구를 만들어 건넴(③) → 그 도구로 실제 요리하는 건 create·zustand(④⑤). persist는 도구 만들어 주고 끝.

## ⑪ useProduct 재실행 & React Query 재갱신 (읽기 흐름)

### useProduct는 "품는 게 아니라 부를 때마다 만들어 내주는 창구"

```ts
const useProduct = (slug) => {...}   // 이름이 담은 건 "함수(레시피)" — 결과값 아님
const supabase = createClient()      // ① 안에서 쓸 도구 "준비" (리턴 ❌, 안 나감)
return useQuery({...})               // ② 밖으로 리턴 = 꾸러미 하나뿐
```

- **안에서 하는 일 ≠ 밖으로 리턴하는 것.** supabase는 내부 재료(주방의 칼·냄비), 리턴은 요리(꾸러미) 하나.
- 꾸러미를 안는 건 useProduct가 아니라 **부른 쪽 변수**: `const { data: product } = useProduct(slug)`.

### 같은 함수가 여러 번 실행된다 (isLoading→data)

```
1차 실행: 응답 전  → { isLoading: true,  data: undefined } → "로딩중" 그림
   (supabase가 { data, error } 응답 → React Query가 리렌더 트리거)
2차 실행: 코드 처음부터 다시 → { isLoading: false, data: 상품 } → 상품 화면  ← 재갱신
```

- **다시 실행시키는 방아쇠 = React Query.** (상태 바뀌면 page를 리렌더 → 그 안 useProduct도 재실행)
- 갱신되는 곳 = **부른 컴포넌트(page)**, import 자리가 아님.
- 꾸러미에 `isLoading`·`error`가 같이 있는 이유 = **실행 시점마다 상태가 다르니까.**

### React Query가 하는 일 = "가공"이 아니라 "담고 상태 갱신"

- data 내용을 **바꾸지 않음.** supabase가 준 그대로를 `data` 칸에 담고, `isLoading`을 false로, error 있으면 error 칸에.
- 즉 **정제(가공) ❌ / 포장·상태표시 ⭕.**

### 읽기 방향 주의 (자꾸 뒤집히는 곳)

- **읽기(select) = 데이터를 "던지는" 게 아니라 "요청 보내고 받는" 것.** (던지는 건 저장(insert) 때)
- `.select('*')` = **전체 열(칸)** (전체 행 ❌) / `.eq(...)` = **행(줄) 고르기** / `.single()` = **조건 맞는 한 행을 객체 하나로** (전체 행 ❌).
- 🍽️ 식당: 주문서를 보내고(요청) 음식을 받는다(data). 음식을 주방에 던지지 않는다.

## ⑫ slug의 출처 & 한 줄의 양쪽 방향

### slug는 URL(주소)에서 온다

```
URL: /products/beads-01
폴더: src/app/(shop)/products/[slug]/page.tsx   ← [slug]=동적 구간(그 자리를 slug로 받겠다)
```

```ts
const { slug } = useParams<{ slug: string }>()
//      │         │                └─ 타입: slug는 문자열
//      │         └─ URL에서 값 꺼내주는 도구(부름) → { slug: 'beads-01' }
//      └─ 구조분해로 slug만 꺼냄 → 'beads-01'
```

세 개의 slug가 이어짐: **폴더 `[slug]`**(약속) → **useParams()의 slug**(URL에서 꺼낸 실제 값) → **useProduct(slug)**(조회에 넘김).

### 인자(넣기, page) → 매개변수(받기, 정의) → supabase 요청

```ts
// page.tsx — slug를 "인자"로 넣음
const { data: product } = useProduct(slug)

// useProducts.ts — slug를 "매개변수"로 받음
export const useProduct = (slug: string) => {
  ...
  .eq('slug', slug)   // 받은 slug로 supabase에 요청 (앞='slug' 컬럼명 / 뒤=받은 값)
```

- 같은 slug가 자리에 따라 이름 다름: **넣는 쪽=인자 / 받는 쪽=매개변수.**
- 인자 모양은 **함수 규칙 따라** 다름: `useProduct(slug)`=문자열 하나 / `addItem({...})`=객체 하나. (둘 다 인자)

### ★ 이 한 줄은 왼쪽/오른쪽이 하는 일이 다르다 (자꾸 뒤집힘)

```ts
const { data: product, isLoading, error } = useProduct(slug)
//     └────────── 왼쪽 ──────────┘         └──── 오른쪽 ────┘
//     꾸러미를 "꺼내는" 쪽                  slug "넣어 부르는" 쪽
```

**순서: 오른쪽 먼저 → 왼쪽**

```
① 오른쪽: useProduct(slug)   ← slug를 "넣고" 부름 (꺼내는 게 아님!)
② useProduct 실행 → 꾸러미 { data, isLoading, error } 리턴
③ 왼쪽: const { ... } = ...   ← 그 꾸러미에서 구조분해로 꺼냄
```

- ⚠️ **slug = 넣는 것**(인자), 꺼내는 것 ❌
- ⚠️ **data/isLoading/error = useProduct가 리턴한 "꾸러미" 안**에 있음. **slug 안 ❌.**
- 🍜 slug=주문번호(넣기) / useProduct=창구 / 꾸러미=나온 세트 / data·isLoading·error=세트 안 반찬(주문번호 안 아님).

### 이 줄에서 조회가 "끝나는" 게 아니다 (⑪ 참고)

- 이 줄은 **지금 상태를 꺼내는 창구.** 조회는 백그라운드에서 진행 → 끝나면 리렌더로 이 줄 재실행.
- 그래서 아래에 `if (isLoading) ...` / `if (error) ...` 가드 후 product 사용.

## ✅ 한 눈 요약

```
큰 깨달음:  함수 = 값을 하나 뱉는(return) 상자. 그 값이 객체일 수도 있다.

① 뱉는다 = return       (=> 뒤 바로 값 = return 생략)
② 객체도 뱉는다          => ({...}) 소괄호 = "이 객체를 return"  (붕어빵)
③ 이름() = 부른다        괄호 열면 호출 / useQuery(...) = 부른 결과를 리턴
④ 인자 IN / return OUT   방향 반대. 넣은 걸 도로 뱉는 게 아니라 새 결과를 뱉음
```
