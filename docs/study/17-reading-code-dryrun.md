# 17. 코드 쉽게 읽는 법 (바깥→안) + addItem "두 없으면" 구분 + dry run

> 한 줄: **코드는 글처럼 왼→오른쪽으로 읽지 말고, 양파처럼 바깥→안으로 껍질을 벗긴다. 각 층에서 "구조(뼈대) 먼저, 세부는 나중". 그리고 addItem엔 "없으면"이 두 개다 — 바깥 if(존재 여부)와 map 삼항(이 칸이 그놈이냐)은 다른 층.**
> set·클로저·병합 [[16-set-closure-write]] · find/existing [[15-find-dot-notation]] · 중첩 구조 [[16-set-closure-write]] 6번

---

## 뜯은 코드

```ts
addItem: (item) =>
  set((state) => {
    const existing = state.items.find((i) => i.id === item.id)
    if (existing) {
      return { items: state.items.map((i) =>
        i.id === item.id ? { ...i, quantity: i.quantity + 1 } : i) }
    }
    return { items: [...state.items, { ...item, quantity: 1 }] }
  })
```

---

## 1. ⭐ 코드 쉽게 읽는 3원칙

### ① 왼→오른쪽 X, 바깥→안으로 껍질 벗기기 🧅

초보가 힘든 이유 = 글처럼 한 글자씩 읽어서. 코드는 **양파처럼 층**. 바깥 껍질부터.

### ② 뼈대 먼저, 살은 나중 (디테일 접기)

복잡한 줄은 일단 **뭉개서 뼈대만**. 세부(find·map·spread)는 나중.

### ③ 한 줄씩 우리말 번역 + 실제 값 넣어보기(dry run)

---

## 2. "모양(뼈대)" = 세부 지우고 구조만 (blur 🫥)

이미지를 흐리게 하면 레이아웃만 보이듯, 코드도 세부를 지우면 구조만 남는다.

```
🔍 원본        find·map·spread 다 보임
🌫️ 살짝 흐림    const existing = 찾기 / if 있으면 return A / return B
🌫️🌫️ 완전 흐림  받아서 → 찾고 → 있으면 A / 없으면 B     ← 이게 "뼈대"
```

→ addItem 뼈대 한 줄: **"상품 받아서, 이미 담긴 거 찾고, 있으면 수량+1 / 없으면 새로 추가."**

---

## 3. 읽는 순서 — 바깥에서 안으로 (3단계)

```
1단계 (바깥 껍질):  addItem: (item) => set(...)
                   "상품 받아 스토어 바꾸는 함수구나"  ← { } 안은 아직 안 봄
2단계 (블록 안 구조): set((state) => { 찾고 → 있으면 A / 없으면 B })
                   코드블록 { } 안의 "뼈대"만
3단계 (세부):        A·B 안의 map·spread 하나씩 펼쳐 보기
```

🏢 건물 비유: 밖에서 "3층 건물이네"(껍질) → 안 들어가 "방 배치"(구조) → 각 방 가구(세부). **처음부터 가구 다 보려니 어지러운 것.**

- 각 층에서 규칙은 항상 **"구조 먼저 → 세부 나중"**.

---

## 4. ⭐⭐ addItem엔 "없으면"이 두 개다 (다른 층!)

가장 헷갈리는 함정. if가 서로 다른 층에 두 개 있다.

### 없으면 ① — 바깥 `if (existing)` : "장바구니에 그 상품 자체가 있나?"

```ts
if (existing) {                                       // 있으면 → 수량+1 (map)
  return { items: 수량+1한 새 배열 }
}
return { items: [...state.items, { ...item, quantity: 1 }] }  // 없으면 = 새로 추가
```

- **있으면** = 이미 담긴 상품 → 그놈 수량 +1
- **없으면①** = 처음 담는 상품 → 배열 맨 뒤에 **새로 추가**

### 없으면 ② — map 안 삼항 `: i` : "지금 이 칸이 그 상품이야?"

```ts
state.items.map((i) =>
  i.id === item.id ? { ...i, quantity: i.quantity + 1 } : i
)                                                          ─┬─
                                       이 칸이 그놈 아니면 → 그대로 둠
```

- map은 배열 **전체를 도니까** 칸마다 검사
- **이 칸이 그놈** → 수량 +1 / **아니면②** → `i` 그대로 (안 건드림)

### 두 "없으면" 한눈 구분

```
없으면 ① (바깥 if else)  = "그 상품 자체가 장바구니에 없음"  → 새로 추가
없으면 ② (map 삼항 :i)   = "지금 이 칸이 그 상품이 아님"     → 그대로 둠
① = 상품 있냐 없냐(전체 판단) / ② = 이 칸이 그놈이냐(한 칸씩)
```

---

## 5. ⭐ 마스터 비법 = 손으로 값 따라가기 (dry run)

읽기만 하면 안 남는다. **실제 값 넣고 손으로 굴려야** 근육이 생김.

### 예시 A — `[사과(2), 배(1)]`에서 사과 또 담기

```
바깥 if: 사과 있나? → 있음(existing) → map 돌림
  사과 칸: id 같음 → {...사과, quantity:3}   (없으면① 아님)
  배 칸:   id 다름 → 배 그대로 (: i)          (없으면②)
결과: [사과(3), 배(1)]
```

### 예시 B — `[사과(2), 배(1)]`에서 감키링 처음 담기

```
바깥 if: 감키링 있나? → 없음(undefined) → 아래 return
  [...state.items, {...감키링, quantity:1}]     (없으면①: 새로 추가)
결과: [사과(2), 배(1), 감키링(1)]
```

→ dry run 2~3개 굴리면 이 블록은 완전히 내 것이 됨.

## ✅ 한 눈 요약

```
코드 읽는 법:
  ① 바깥→안 껍질 벗기기 (글처럼 왼→오른쪽 X, 양파 🧅)
  ② 뼈대 먼저 세부 나중 (blur해서 구조만)
  ③ 우리말 번역 + 실제 값 dry run
  순서: 바깥 껍질 → 코드블록 안 구조 → 세부 (각 층 "구조 먼저")

addItem 뼈대: 받아서 → 찾고 → 있으면 수량+1 / 없으면 새로 추가

⭐ "없으면" 두 개 (다른 층!):
  ① 바깥 if else = 상품 자체가 없음 → [...state.items, 새상품] 추가
  ② map 삼항 :i  = 이 칸이 그놈 아님 → i 그대로

마스터 = dry run (실제 값 손으로 따라가기)
  사과 또 담기 → 사과칸 +1, 배칸 그대로 / 감키링 처음 → 맨 뒤 추가
```
