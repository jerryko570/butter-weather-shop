# 21. state는 클로저 아님 + 점표기법 ≠ 클로저 + 메서드는 혼자 못 시작 + return은 맨 마지막

> 한 줄: **`state`는 콜백이 직접 받은 매개변수라 클로저가 아니고(클로저는 `item`처럼 바깥 함수 거를 꺼내 쓸 때), 점표기법은 "객체면 꺼낸다"일 뿐 클로저랑 별개다. 메서드(.map/.some)는 혼자 못 시작하고 앞의 배열에 붙는다. `return`은 먼저가 아니라 "뒤의 값을 다 만든 뒤 맨 마지막"에 내보낸다. `map`은 배열을, 삼항은 칸 하나를 만든다. `i`는 `CartItem` 모양이라 `i.quantity`가 된다.**
> 클로저 [[13-closure]] · find/점표기법 [[15-find-dot-notation]] · return [[14-return]] · if/상태/quantity [[20-if-state-quantity]] · 실습 [[practice-01-add-to-cart]]

## 오늘 뜯은 코드

```ts
addItem: (item) =>
  set((state) => {
    const existing = state.items.some((i) => i.id === item.id)
    if (existing) {
      return {
        items: state.items.map((i) =>
          i.id === item.id ? { ...i, quantity: i.quantity + 1 } : i
        ),
      }
    }
    return { items: [...state.items, { ...item, quantity: 1 }] }
  }),
```

---

## 1. ⭐ `state`는 클로저가 아니다 — `item`만 클로저

콜백 몸통에서 `state`랑 `item` 둘 다 쓰지만, **출처가 다르다.**

```ts
addItem: (item) =>        // item은 여기(바깥 함수)에 선언됨
  set((state) => {        // state는 여기(이 콜백)에 선언됨
    state.items ...       // state = 내 매개변수 (받음)      → 클로저 ❌
    item.id ...           // item  = 바깥 함수 거 (꺼내 씀)   → 클로저 ✅
  })
```

**판별법: "이 콜백 `( )` 괄호에 그 이름이 적혀 있나?"**

| 값 | `(state) =>` 괄호에 있나? | 결론 |
| ----- | --------------------------- | ----------- |
| `state` | ✅ 있음 → 내 매개변수 (받음) | 클로저 **아님** |
| `item` | ❌ 없음 → addItem 거 (꺼내 씀) | **클로저** |

- **매개변수를 몸통에서 쓰는 건 "꺼내는" 게 아니라 "받은 걸 쓰는" 것** → 클로저 아님.
- **클로저 = 내 매개변수가 아닌데 바깥 함수 값을 꺼내 쓸 때.**
- 우유·물·주스 비유: `state` = 주스(내 매개변수) / `item` = 우유·물(바깥 거). → [[13-closure]]
- 택배 비유: `state` = 나한테 직접 온 택배(내 거) / `item` = 옆집(addItem)에서 빌려온 거.

---

## 2. ⭐ 점표기법 ≠ 클로저 (완전 다른 개념)

반복해서 섞였던 지점. **점표기법은 클로저랑 상관없다.**

```
점표기법 = 객체에서 키 꺼내기 (객체.키)   → "이게 객체냐?"만 봄 (출처 무관)
클로저   = 바깥 함수 값을 꺼내 쓰기        → "어디서 선언됐냐?"가 핵심
```

셋 다 점표기법인데 출처는 제각각 (그래서 둘은 별개):

```ts
state.items        // state = 내 매개변수   (클로저 ❌)  ← 점은 됨
item.id            // item  = 바깥 함수 거   (클로저 ✅)  ← 점은 됨
i.id               // i     = some 매개변수  (클로저 ❌)  ← 점은 됨
```

- `state.items`도 점표기법이지만 state는 클로저가 아님 → **둘이 별개라는 증거.**
- 전에 스스로 도달했던 정리: **"매개변수든 변수든 객체이기만 하면 점으로 꺼낸다."** 그게 정답.

---

## 3. ⭐ 점(`.`) = 근(root)에서 한 겹씩 더 딥하게

받은 매개변수(state)를 **기점(출발점)** 으로, 점을 찍을 때마다 한 겹씩 안으로.

```ts
state                 // 받은 상자 (근, 0층 전체)
state.items           // 한 겹 ↓ (items 배열)
state.items[0]        // 더 ↓   (첫 상품)
state.items[0].id     // 더 ↓   (그 상품의 id)
```

- `state` 자체는 **꺼내는 게 아니라 "받는" 것**(set이 통째로 줌). 그걸 기점으로 **점 찍어 들어간다.**
- 왜 state가 "먼저"냐 = 전체 상자를 먼저 쥐어야 그 안의 items를 꺼낼 수 있어서.
- 점표기법은 **왼 → 오** (전체 → 세부)로 좁혀 읽는다.

### state는 "추가"가 아니라 "통째로 채워짐"

```
(state) 빈칸 → zustand가 "현재 store 전체"를 통째로 채움 → state.items로 꺼냄
```

- state에 뭔가 **덧붙는(추가)** 게 아니라, state가 **곧 현재 store 전체**가 됨(한 번에).
- set은 items만 주는 게 아니라 **스토어 전체**를 주입 → 내가 필요한 칸(items)을 점으로 골라 꺼냄.

## 4. ⭐ 메서드(.map/.some/.filter)는 혼자 못 시작한다

```ts
state.items.map(...)
 ①     ②      ③
```

| | 뭐냐 | 점이 하는 일 |
| --------- | --------------------- | ------------- |
| ① `state` | 근(root) = 출발점 | — |
| ② `.items` | state에서 꺼낸 **배열** | 값 꺼내기 |
| ③ `.map(...)` | 그 배열에 붙은 **메서드** | 동작 시키기 (`()` 붙음) |

- **메서드는 앞에 뭔가 있어야 붙는다.** `.map(...)` 혼자는 "뭘 map 하라고?" → 불가능.
- 점의 두 역할: `.items` = **값 꺼내기** / `.map()` = **동작 시키기**(뒤에 `()`).
- **메서드는 타입을 본다** — `.map .some .filter .find`는 **배열 전용**.
  - `state.items.map(...)` ✅ (items는 배열) / `state.map(...)` ❌ (state는 객체 → 에러)

## 5. ⭐ `return`은 "먼저"가 아니라 "맨 마지막" — 뒤의 값을 다 만든 뒤 내보낸다

```ts
return 2 + 3   // "return 하고 나서 2+3" ❌ → "2+3=5 먼저 계산 → 5를 내보냄" ✅
```

이 코드의 진짜 순서 (오른쪽 → 왼쪽):

```ts
return { items: state.items.map((i) => ...) }
```

```
① state.items.map(...) 먼저 실행   → [사과, 바나나(2)] 새 배열 생김
② items: [...] 로 객체 완성
③ return { items: [...] }          → 그 객체를 내보냄 (맨 마지막)
```

- **map이 먼저 돌아 배열(값)을 만들고 → 객체 완성 → return은 마지막.**
- 선물 비유: 선물(값)을 먼저 만들어야 상자에 담아 건넨다. 빈손으로 "자!"(return) 먼저 하고 선물 만드는 거 아님.

### 값(value) 자리엔 "식"도 온다

```ts
{ items: 5 }                      // 값 = 숫자
{ items: state.items.map(...) }   // 값 = "실행하면 배열이 나오는 식" ✅
```

- "값"은 완성된 단순한 것일 필요 없다. **"값을 만들어내는 식"이면 OK.**
- 그래서 value 자리에서도 점표기법 체인을 쓴다.

---

## 6. ⭐ `map`은 배열을, 삼항은 "칸 하나"를 만든다 (두 층)

```ts
state.items.map((i) =>                                    // ① map: 새 배열 만들기
  i.id === item.id ? { ...i, quantity: i.quantity + 1 } : i   // ② 삼항: 칸 하나 정하기
)
```

| | 하는 일 | 결과물 |
| --------- | ----------------------- | ------------- |
| ① `map` | 전체 돌며 **새 배열** 만듦 | 배열 |
| ② 삼항 | 각 **칸 하나(i)** 를 정함 | 칸(객체 1개 or i) |

- **삼항은 "새 배열"을 만드는 게 아니다** — "한 칸"만 내놓는다.
  - 맞으면 → `{ ...i, quantity+1 }` (그 칸을 복사+1한 새 객체)
  - 다르면 → `i` (그 칸 그대로)
- **map이 그 칸들을 모아 새 배열로** 완성.

## 7. ⭐ `if (existing)` vs `map`의 id 체크 — 왜 두 번?

"이미 if에서 걸렀는데 왜 map에서 또 체크?" → **일이 다르고, if는 아무것도 거르지 않았다.**

| | 하는 일 | 질문 |
| ---------------- | ------------- | ------------------------ |
| `if (existing)` (some) | **존재 확인** | "있긴 있나?" (전체에 하나라도) |
| `map`의 `i.id === item.id` | **위치 찾기** | "**어느 칸**이냐?" (칸마다) |

- `existing`엔 **true/false만** 담긴다 → "있다"만 알지 **어느 칸인진 모름.**
- 장바구니엔 여전히 상품이 **전부 다 있다**(if는 안 지움). → map이 전체를 **다시 돌며** 맞는 칸을 찾아야 함.
- map은 **모든 칸을 방문**하니까, 체크 안 하면 전부 +1 돼버림 → 그래서 `? : i`로 **맞는 것만** 고름.
- 교실 비유: `if` = "철수 있어요?"(있다/없다) / `map` = 한 명씩 "너 철수야?"(철수만 상 주고 나머지 그대로).

## 8. ⭐ `{ ...i, quantity: i.quantity + 1 }` = i를 "복사한 새 객체" (i 자체 ❌)

```
i(원본)  = { id:'바나나', ..., quantity: 1 }   ← 그대로 남음 (안 건드림)
              │ ...i 복사 + quantity만 +1
              ▼
새 객체   = { id:'바나나', ..., quantity: 2 }   ← 복사본, 수량만 2
```

- `...i` = i 내용(id·name·price…) **복사** / `quantity: i.quantity + 1` = quantity만 **덮어씀**.
- **i 자체가 아니라 "i를 닮은 새 객체"** (복사기). 원본 i는 그대로 = 불변성.
- `i.quantity` = "지금 수량"을 i에서 **읽어서** +1 → 새 복사본에 **써넣음** (읽는 곳 ≠ 쓰는 곳).

### `i`는 `CartItem` 모양이라 `i.quantity`가 된다

```ts
interface CartItem { id; slug; name; ...; quantity: number }  // 설계도 (칸이 "있다" 정의)
i = { id:'바나나', ..., quantity: 1 }                          // 실제 객체 (값 1 있음)
i.quantity → 1                                                // quantity 칸 꺼냄
```

- interface = **설계도**(모양만, 값 없음) / 실제 값(1)은 **진짜 객체 i** 안에.
- interface가 "quantity 있다"고 보장 → 그래서 `i.quantity`를 쓸 수 있음(없으면 TS 빨간 줄).

---

## 9. 없을 때 분기 — `+1`이 아니라 `1`, `items`가 아니라 `item`

```ts
return { items: [...state.items, { ...item, quantity: 1 }] }
```

- `...state.items` = 원래 있던 물건들 복사 (**items**, 봉투 🛍️)
- `{ ...item, quantity: 1 }` = 새로 담는 물건 하나 (**item**, 🍌) + 처음이라 **1**

| | 쓰는 것 | 왜 |
| ---------- | --------------------- | ------------------------- |
| 있을 때 (map, `i`) | `quantity: i.quantity + 1` | i엔 **지금 수량 있음** → +1 |
| 없을 때 (`item`) | `quantity: 1` | item엔 **수량 없음** → 처음이라 1 |

- **`items`(복수, 봉투/배열) vs `item`(단수, 새 물건 하나)** — s 하나 차이, 완전 다른 것.
- `[ ]` = 새 봉투(배열) / `{ }` = 물건 하나(객체) / `...` = 복사해 넣기 / `,` = "그리고".

---

## 10. `return { items: 값 }` = "어느 칸을 뭘로 바꿀지" 쪽지 (병합)

```ts
return { items: 새배열 }
         ─┬──  ──┬──
         키     값
```

- `items`(키) = 스토어의 **어느 칸**인지 = 주소/라벨
- 새배열(값) = 그 칸에 넣을 **새 내용**
- set은 **그 키만 갈아끼우고 나머지(isOpen 등)는 그대로** = **병합(merge)**.
- "추가"가 아니라 **"교체"**(items 칸을 새 배열로 통째로 갈아끼움). 서랍장 비유: items 서랍만 새 내용으로.

## 한 줄 정리 모음

1. `state` = 내 매개변수(받음) → **클로저 아님** / `item` = 바깥 거(꺼냄) → **클로저**
2. **점표기법 ≠ 클로저** — 점은 "객체면 꺼낸다"(출처 무관)
3. 점 = 근(root)에서 **한 겹씩 더 딥하게**, state는 "받아서" 기점으로
4. 메서드는 **혼자 못 시작** — 앞의 배열에 붙고, 타입을 본다(배열 전용)
5. `return`은 **맨 마지막** — 뒤의 값을 다 만든 뒤 내보냄, 값 자리엔 식도 OK
6. `map` = 배열 / 삼항 = 칸 하나
7. `if` = "있나?"(존재) / `map` 체크 = "어느 칸?"(위치) — if는 안 거름
8. `{ ...i, quantity+1 }` = i **복사본**(자체 아님), `i`는 `CartItem` 모양
9. 없을 때 = `quantity: 1`(+1 아님), `item`(≠ items)
10. `return { items: 값 }` = "어느 칸 뭘로 바꿀지" 라벨 = 병합(교체)
