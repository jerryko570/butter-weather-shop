# 07. 커링 — `create()()` 는 왜 괄호가 두 쌍일까

> 한 줄: **이름 뒤의 `()` = "버튼 누르기(실행)". 어떤 기계는 버튼을 누르면 숫자가 아니라 "또 다른 기계"가 나와서, 버튼을 두 번 눌러야 진짜 결과가 나온다. 그게 `create()(persist(...))`.**
> 이 스토어 코드 자체는 [[05-mutation]](쓰기)·장바구니(Zustand) 편과 이어짐.

---

## 🏭 기계·버튼 비유 (전체 그림)

```
함수 이름 뒤의 ()  = "버튼 누르기 = 실행"
버튼을 누르면      = 기계가 뭔가를 툭 뱉어냄
```

보통 기계는 버튼을 누르면 **숫자**가 나온다:

```js
add(3, 4)   // add 버튼 누름 → 7 이 툭
```

그런데 `create` 는 특이한 기계라서, 버튼을 누르면 **또 다른 기계**가 나온다:

```js
create()    // create 버튼 누름 → 숫자 대신 '새 기계 B' 가 툭
```

그래서 나온 기계(B)도 써야 하니까 **버튼을 한 번 더** 누른다:

```
create   →   [버튼 () ]         →   🏭 새 기계 B 가 툭!
   🏭 B  →   [버튼 (persist) ]  →   📦 스토어가 툭!
```

괄호가 두 쌍인 이유 = **버튼을 두 번 누르니까.**

---

## 1. `()` 있냐 없냐 — 실행이냐, 기계 자체냐 (제일 중요)

```js
test      // 괄호 X = '기계 자체' (아직 아무 일도 안 일어남)
test()    // 괄호 O = '버튼 누름 = 실행' (결과가 나옴)
```

실제 코드에서 이 차이가 버그를 가른다:

```tsx
onClick={handleAddToCart}     // ✅ 괄호 X = 기계를 통째로 넘김 → 클릭할 때 React가 눌러줌
onClick={handleAddToCart()}   // ❌ 괄호 O = 지금 당장 실행돼버림 (클릭 전에 터지는 버그)
```

## 2. 함수가 "함수를 리턴"한다는 것

리턴(결과물)의 종류엔 제한이 없다. 숫자·문자열·배열… 그리고 **함수도** 리턴할 수 있다.

```js
function add(a) {
  return function (b) {   // ← 이 안쪽 함수가 B
    return a + b
  }
}
```

한 줄씩 실행:

```js
add(3)      // add 실행 → a=3. "3 + b 하는 새 함수(B)"를 만들어 리턴 (아직 b는 모름)
add(3)(4)   // 리턴된 B에 4를 넣어 실행 → b=4 → 3 + 4 = 7
```

- `add(3)` 은 **"3을 B에 전달"이 아니다.** `add(3)` 은 add를 실행해서 **B를 만들어 내놓는(리턴) 것**이다.
- B는 미리 존재하지 않는다. 첫 호출이 **그 자리에서 B를 낳는다.**

### 클로저 — 신기한 부분

`add(3)` 이 끝났는데도 안쪽 함수는 `a=3` 을 **계속 기억**한다.

```js
const addThree = add(3)
addThree(4)   // 7  (3을 기억)
addThree(10)  // 13 (여전히 3을 기억)
```

바깥이 준 값을 안쪽 함수가 품고 있는 것 = **클로저**. (이름은 나중에 외워도 됨)

## 3. 그래서 `create<CartStore>()(persist(...))`

```ts
create<CartStore>()(persist(...))
      └─ 타입 확정 ─┘ ↑         ↑
                     │         └─ ② B 버튼 누름 → 📦 스토어가 나옴
                     └─ ① create 버튼 누름 → 🏭 B가 나옴 (리턴)
```

- `create<CartStore>()` — 1차 호출. **타입만 확정**하고(값은 안 줌 → 빈 `()`), **B를 리턴**.
- `(persist(...))` — 2차 호출. 나온 **B를 실행** → 스토어 훅 완성.

### 왜 굳이 두 번 나눠 호출? (TypeScript 꼼수)

`create` 는 제네릭 타입이 두 종류 필요하다:
- `CartStore` — 내 상태 타입 → **내가 직접 적어야 함**
- middleware(persist) 타입 → **TS가 알아서 추론 가능**

문제: TypeScript는 **"하나는 내가, 하나는 너가 추론"이 안 된다** (부분 추론 불가). 전부 적기 아니면 전부 추론, 둘 중 하나.
해결: 호출을 둘로 쪼갠다. `create<CartStore>()` 가 타입을 확정하고, 이어지는 `()` 가 나머지(middleware)를 추론한다.

## 4. 저장되는 건 "알갱이"가 아니라 "기계"

```ts
export const useCartStore = create<CartStore>()(
  persist(
    (set, get) => ({ items: [], addItem: ..., ... }),  // ← 이 객체 = '재료(원두)'
    { name: 'butter-weather-cart' }
  )
)
```

- `{ items, addItem, ... }` 객체 알갱이 = 최종 결과물이 아니라 **스토어 기계 안에 담기는 재료**.
- `useCartStore` 에 저장되는 건 그 재료를 품고 **언제든 꺼내주는 기계(스토어 훅)**.
- 꺼낼 때는 **또 버튼을 눌러** 원하는 재료만 뽑는다:

```ts
const items = useCartStore((s) => s.items)   // 기계 버튼 눌러 items만 뽑기
```

## ✅ 한 눈 요약

```
test           = 기계 자체 (안 누름)
test()         = 버튼 한 번 누름 (실행)
test()()       = 나온 기계를 또 누름 (커링)

create()             → 🏭 B 기계
      (persist(재료)) → 📦 스토어 기계 (재료를 품음)
useCartStore = 스토어 기계 보관
useCartStore(...)    → 기계에서 원하는 재료 꺼내 쓰기
```

- 이름 뒤 `()` = **무조건 실행.** 괄호 없으면 = **기계 자체**.
- 커링 = 버튼 누르면 또 기계가 나와서, **두 번 눌러야** 진짜 결과가 나오는 것.
- `create()()` 의 두 쌍 괄호 = TypeScript가 타입을 나눠 받게 하려는 꼼수.
