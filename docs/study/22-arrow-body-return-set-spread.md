# 22. 화살표 `{ }`는 몸통(코드블록) + return은 "누가 쓰나"로 결정 + set은 받아서(입력)→돌려줌(출력) + 스프레드 두 역할

> 한 줄: **화살표 뒤 `{ }`는 "돌려줄 값"이 아니라 "실행할 몸통(코드블록)"이다. 그 안에 for 몸통·객체가 중첩된다. `return`이 필요한지는 `{ }` 때문이 아니라 "그 결과를 누가 쓰느냐"로 정해진다 — `handleAddToCart`는 아무도 안 써서 생략, `set`·`map`·`some` 콜백은 쓰여서 필수. `set`은 `state`(현재값, zustand가 채워주는 읽기용 입력)를 받아 새 상태를 `return`하면 zustand가 스토어를 그걸로 교체(저장은 state가 아니라 스토어, 바뀐 칸만 병합). 스프레드 `...`는 배열 안에선 원소를, 객체 안에선 키:값을 펼친다.**
> 함수문법 [[11-function-syntax]] · return [[14-return]] · set/쓰기 [[16-set-closure-write]] · state·클로저·점·map [[21-closure-dot-method-return]] · 실습 [[practice-01-add-to-cart]]

## 오늘 뜯은 코드

```ts
// ① page — 클릭의 출발점
const handleAddToCart = () => {
  for (let i = 0; i < quantity; i++) {
    addItem({ id: product.id, slug: product.slug, name: product.name /* ...6칸 */ })
  }
  openCart()
}

// ② cartStore — set 콜백
addItem: (item) =>
  set((state) => {
    const existing = state.items.find((i) => i.id === item.id)
    if (existing) {
      return { items: state.items.map((i) => (i.id === item.id ? { ...i, quantity: i.quantity + 1 } : i)) }
    }
    return { items: [...state.items, { ...item, quantity: 1 }] }
  }),
```

## 1. ⭐ 화살표 함수 두 모양 — `=> 값` vs `=> { 몸통 }`

```ts
() => 값          // 화살표 뒤가 "값"   → 그 값을 바로 돌려줌 (암묵 return, 결과물 O)
() => { 문장들 }   // 화살표 뒤가 "{ }"  → 코드블록(몸통). 문장 실행만 (return 선택)
```

- 화살표 뒤 `{ }`는 **"돌려줄 값"이 아니라 "실행할 몸통"** 이다. (← 여기가 핵심 오해 지점)
- `{ }`를 열면 → 돌려주고 싶을 때 **직접 `return`** 을 써야 한다. 안 쓰면 `undefined`를 돌려줌.
- `( )`로 감싸면 "객체를 바로 돌려주기": `() => ({ ... })` ↔ `() => { return { ... } }` 는 같은 뜻.

### 1-b. ⭐ `{ }` 여부 기준 = **return/void 아니라 "문장이 몇 개냐"**

> ⚠️ 오해: "void(return 없음)라서 `{ }` 생략" ❌ → 진짜 기준은 **"몸통이 한 방이냐 여러 문장이냐".**

```ts
(x) => 식            // 한 방(식 하나)      → { } 생략, 결과 자동 return
(x) => ({ 키: 값 })   // 객체 한 방 돌려주기  → ( )로 감싸 바로 돌려줌
(x) => { 문장들 }     // 여러 문장(const·if) → { } 코드블록, 돌려주려면 return
```

**`removeItem` vs `addItem` 대조** (둘 다 `=> void`인데 `{ }` 여부가 다름 → void 때문이 아님):

```ts
// removeItem — 바깥도 안쪽도 "한 방" → { } 없음
removeItem: (id) => set((state) => ({ items: state.items.filter((i) => i.id !== id) }))
//                └바깥: set 호출 한 방┘ └안쪽: filter 객체 한 방 → ({ })┘

// addItem — 안쪽에 const·if 여러 문장 → { } 코드블록 필요
addItem: (item) => set((state) => {
  const existing = state.items.find((i) => i.id === item.id)  // 문장 ①
  if (existing) { return {...} }                              // 문장 ②
  return {...}                                                // 문장 ③
})
```

- `removeItem`이 `{ }` 없는 건 void라서가 아니라 **filter 한 방으로 끝나서.**
- `addItem`이 `{ }` 쓰는 건 **const·if 여러 문장**이 필요해서. (둘 다 void인데 모양이 갈림)

## 2. ⭐ `{ }` 세 종류 + 중첩 — `handleAddToCart` 해부

```ts
const handleAddToCart = () => {        // ⓐ 함수 몸통 { }  = 코드블록 (바깥)
  for (let i = 0; i < quantity; i++) { // ⓑ for 몸통 { }   = 코드블록 (안쪽, 중첩)
    addItem({ id: product.id, ... })   // ⓒ 넘기는 상품 { } = 객체 ★ 코드블록 아님!
  }
  openCart()
}
```

| | 뭐냐 | 종류 |
| ------------------- | ----------- | ------------------ |
| ⓐ `() => { }` | 함수 몸통 | **코드블록** (동작 = 동사) |
| ⓑ `for () { }` | 반복 몸통 | **코드블록** (동작 = 동사) |
| ⓒ `addItem({ })` | 넘기는 상품 데이터 | **객체** (데이터 = 명사) |

- ⓐ ⓑ는 "코드블록 안의 코드블록" (중첩). ⓒ는 같은 `{ }` 기호지만 **객체**.
- 판별: **동작(문장)을 담으면 코드블록 / `키: 값`을 담으면 객체.**

---

## 3. ⭐ `return`은 `{ }` 때문이 아니라 "그 결과를 **누가 쓰나**"로 결정

| 함수 | return | 이유 |
| ----------------------- | ------- | ------------------------- |
| `handleAddToCart` | **불필요** | 그냥 **동작**만, 돌려준 걸 **아무도 안 씀** |
| `set` 콜백 `(state) => {}` | **필수** | set이 **새 상태**로 **씀** |
| `map` 콜백 `(i) => ...` | **필수** | map이 그 값으로 **새 배열을 만듦** |
| `some`/`find` 콜백 | **필수** | 그 true/false·객체를 some·find가 **씀** |

- `handleAddToCart`는 `onClick={handleAddToCart}`로 **실행만** 될 뿐, 돌려준 값을 쓰는 사람이 없다 → return 생략.
- `{ }`를 봤을 때 "return 있어야 하나?"가 아니라 → **"이 함수가 돌려주는 걸 누가 쓰나?"** 를 먼저 물어라. 쓰면 return, 안 쓰면 생략.

> 🔑 **핵심 한 줄:** `{ }`를 보면 "return인가?" 말고 **"여기 명령들을 담았구나"** 라고 먼저 읽어라. `return`은 그 안에 **값을 돌려줄 때만** 추가로 쓰는 것이고, **동작만 하는 함수엔 아예 없다.**

## 4. ⭐ 코드블록 `{ }` 안에서 "객체를 내놓으려면" `return { }`로 감싸야 — `items:` 라벨 함정

```ts
if (existing) {
  items: state.items.map(...)        // ❌ 이 { }는 코드블록 → items: 는 "라벨"로 읽힘 (객체 X)
}

if (existing) {
  return { items: state.items.map(...) }  // ✅ return { } 로 감싸야 비로소 "객체"
}
```

- `if () { }`의 `{ }`는 **코드블록**이다. 그 안에 맨몸으로 `items: ...`를 쓰면 JS는 **객체 속성이 아니라 "라벨(label)"** 로 해석한다 → 의도한 "새 상태 객체"가 안 됨.
- 코드블록 안에서 객체를 결과로 내놓으려면 **반드시 `return { }`** 로 감싼다. `return {` 가 있어야 그 `{ }`가 "객체"로 읽힌다.

## 5. ⭐ `set`의 입출력 모델 — `state`는 받는 입력, `return`은 스토어를 교체하는 출력

```ts
set((state) => {
  return { items: [...] }
})
```

| | 방향 | 정체 |
| --------------- | ------- | ----------------------------- |
| `state` | **들어옴 (입력)** | zustand가 "현재 스토어 전체"를 **채워준** 읽기용 스냅샷 |
| `return { ... }` | **나감 (출력)** | 내가 만든 **새 상태** |

- **저장되는 곳은 `state`가 아니다.** `state`는 그냥 현재값을 **보여주러 들어온 입력**.
- zustand가 `return`값을 받아 → 내부의 **진짜 저장소(store)를 갈아끼운다.** ← 여기가 진짜 저장.
- 요리사 비유: `state` = 요리사가 "지금 선반 이래요" 보여준 것 / `return` = 내가 만든 새 장바구니 / **저장** = 요리사가 선반(스토어)에 올려놓음.
- **얕은 병합**: `{ items: ... }`만 돌려줘도 `isOpen` 등 나머지 칸은 유지됨. 바뀐 칸만 갈아끼운다.
- 다음에 또 `set`이 불리면, zustand는 **갈아끼운 최신 스토어**를 다시 `state`로 보여줌 → 그래서 수량이 쌓여간다.

## 6. ⭐ `set(직접 객체)` vs `set(콜백)` — 기존 상태를 봐야 하면 콜백

```ts
openCart: () => set({ isOpen: true })        // 기존 볼 필요 X → 새 값 직접 줌
addItem:  (item) => set((state) => ...)      // 기존 items에 더해야 함 → 기존을 "받아야" 함 → 콜백
```

- 기존 값을 **읽어서** 새 값을 만들어야 하면 (append·+1 등) → `(state) =>` **콜백** 형태.
- 그냥 통째로 새 값으로 바꾸면 되면 → `set({ ... })` **직접** 형태.

---

## 7. ⭐ 스프레드 `...` — 같은 기호, 두 역할 (배열이냐 객체냐)

```ts
items: [...state.items, { ...item, quantity: 1 }]
//       └───①───┘        └──②──┘
```

| | 어디에 붙나 | 뭘 펼치나 | 예 |
| ----------------- | -------------- | ------------ | ---------------------------------- |
| ① `...state.items` | **배열 `[ ]`** 안 | **원소**들 (상품들) | `[키링, 팔찌] → 키링, 팔찌` |
| ② `...item` | **객체 `{ }`** 안 | **키:값**들 (id·name…) | `{id,name} → id:…, name:…` |

- `...`는 "안에 든 걸 쏟아낸다". **배열 안 → 원소 펼침 / 객체 안 → 키:값 펼침.**
- `{ ...item, quantity: 1 }` = item의 모든 칸 복사 + `quantity: 1`만 얹기 (처음 담으니 1).
- 전부 **새 배열/새 객체**를 만든다 → 원본 안 건드림(불변성). [[21-closure-dot-method-return]] 8·9와 연결.

## 한 줄 정리 모음

1. 화살표 뒤 `{ }` = **돌려줄 값이 아니라 실행할 몸통(코드블록)**. 돌려주려면 직접 `return`.
2. `{ }` 세 종류: 함수 몸통·for 몸통 = **코드블록(동사)** / `addItem({})` = **객체(명사)**. ⓐⓑ는 중첩.
3. `return` 여부는 `{ }`가 아니라 **"결과를 누가 쓰나"** — 안 쓰면 생략(handleAddToCart), 쓰면 필수(set·map·some).
4. 코드블록 `{ }` 안에서 객체 내놓으려면 **`return { }`로 감싸기** (안 그러면 `items:`가 라벨).
5. `set`: `state` = **읽으러 들어온 입력**(zustand가 채움) / `return`값 = **스토어를 교체하는 출력**. 저장은 스토어에, 바뀐 칸만 **병합**.
6. `set(직접객체)` vs `set(콜백)` — 기존 상태 봐야 하면 **콜백**.
7. 스프레드 `...` = **배열 안이면 원소**, **객체 안이면 키:값**을 펼침. 늘 새 배열/새 객체(불변성).
